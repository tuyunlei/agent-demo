## 核心洞察

工具不只在服务端执行，也可以在客户端执行（调用移动端系统 API）。

## 三种工具执行位置

- **服务端工具**：搜索 API、LLM 调用、数据库查询
- **客户端工具**：系统日历、通讯录、本地通知/提醒、相机/相册、GPS 定位、剪贴板、闹钟
- **混合工具**：日程管理（Google Calendar vs 系统日历）、文件（云存储 vs 本地）

## 调用流程变化

传统：用户 → 服务端 → LLM → 服务端工具 → LLM → 用户

新增：用户 → 服务端 → LLM → **服务端下发指令给客户端** → **客户端执行** → **结果回传服务端** → LLM → 用户

## gRPC 的优势

server streaming / bidirectional streaming 天然支持"服务端向客户端下发工具执行指令"。

## 待深入讨论的问题

- [ ] Tool 抽象需要 `execution_target` 概念（SERVER / CLIENT / HYBRID）
- [ ] 客户端不在线时的降级策略
- [ ] 客户端系统权限处理（用户未授权时 agent 怎么应对）
- [ ] 安全性：客户端工具白名单、敏感操作用户确认
- [ ] 工具能力发现：服务端怎么知道客户端支持哪些工具（不同设备能力不同）

## 架构影响

- 工具系统抽象层必须从设计之初就考虑 client-side execution
- gRPC 接口设计需要包含工具下发和结果回传的 message 定义
- 客户端需要实现一个 tool executor 模块
