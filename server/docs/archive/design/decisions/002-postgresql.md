# ADR-002: 数据存储使用 PostgreSQL

**日期**：2026-02-15
**状态**：已决定

## 背景

多用户平台需要持久化存储用户信息、会话消息、Agent 配置。需要选择数据库方案。

## 决策

使用 PostgreSQL 作为主数据存储。MVP 单实例，未来按需扩展（读写分离 → 分区表 → 分库分表）。

## 考虑过的替代方案

- **SQLite**：嵌入式，零运维。但并发写入是瓶颈（单写者），多租户场景不适合。
- **Database-per-tenant**：每用户独立数据库，隔离彻底。但 C 端场景运维复杂度爆炸，不适合。
- **NoSQL (MongoDB 等)**：灵活 schema。但关系型数据（用户-会话-消息）用 PG 更自然。

## 后果

- ✅ 天然支持高并发读写
- ✅ 扩展路径平滑（索引优化 → 读写分离 → 分区表 → 分库分表）
- ✅ Rust 生态成熟（sqlx / diesel）
- ✅ 原生支持 JSONB（灵活存储 agent 配置）、分区表
- ⚠️ 多一个运维依赖（需要跑 PG 进程）
- ⚠️ 未来可能需要加 Redis 做缓存层（活跃会话、限流计数）

## 设计约束

- **所有查询必须带 user_id 条件**——这是未来分片的天然分片键
- 未来加 Redis 是增量变更，不需要改动 PG 部分
