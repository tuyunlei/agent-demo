# ADR-001: MVP 采用单体架构 + 模块化边界

**日期**：2026-02-15
**状态**：已决定

## 背景

系统有多个逻辑组件（API Gateway、Agent Service、LLM Gateway、Tool Runtime、Channel Adapter），需要决定部署形态。团队 1 人，MVP 一周。

## 决策

MVP 阶段全部合成一个 Rust binary，代码层面用 module 和 trait 做好边界。

## 考虑过的替代方案

- **微服务拆分**：每个组件独立部署。适合大团队，1 人运维多个服务不现实。
- **部分拆分**：核心服务 + 数据库分开。增加了部署复杂度但收益不大。

## 后果

- ✅ 开发速度快，一个进程跑起来就行
- ✅ 不需要处理服务间通信、服务发现等问题
- ✅ 模块化边界保证未来可以拆分
- ⚠️ 未来要拆服务时需要一些重构工作（但 trait 边界降低了成本）
- ⚠️ 单进程意味着一个 panic 可能整体挂掉
