# 002 - 约束清单

*2026-02-15 讨论*

## 硬约束（不可妥协）

| 类别 | 约束 | 说明 |
|------|------|------|
| 团队 | 1 人 | 涂涂独立开发，练手为主 |
| 时间 | MVP 一周 | 非常激进，给朋友看效果 |
| 预算 | ~$100 | 当前阶段练手预算 |
| 后端语言 | Rust | 明确倾向，AI 辅助开发弥补速度 |
| 客户端 | Native 优先 | 全平台目标（Android/iOS/Harmony/Web/MiniApp），但实现做近 |
| LLM | 解耦 | 架构上不绑定具体 LLM，像 OpenClaw 一样可切换 |

## 设计原则

- **架构想远，实现做近**：架构考虑多租户、全平台、可扩展，但一周内只做最小集
- **面向普通人**：零技术门槛，开箱即用
- **千人千面**：每个用户的 agent 是独立的、有个性的、"属于自己的"

## MVP 必须有

- [x] 手机 app（先做一个平台）
- [x] 邀请码 + passkey/设备密钥绑定（替代登录注册）
- [x] Onboarding 聊天流程（通过对话建立 agent 设定）
- [x] 聊天界面 + 流式回复
- [x] 对话历史持久化
- [x] Agent 人格/个性（千人千面）

## MVP 暂不做

- [ ] 传统注册/登录系统
- [ ] Agent 主动推送消息
- [ ] 全平台客户端
- [ ] 高级工具能力（文件、代码执行等）

## 待定（需要后续讨论）

- Onboarding 具体流程设计
- 如何让用户知道 agent 能做什么
- MVP 先做哪个平台（Android？iOS？Web 先凑合？）
