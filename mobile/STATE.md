## 已定的架构决策

### 分层（四层，依赖只能向下）
1. **应用集成层**：启动、服务注册、Root 页面
2. **业务层**：按业务垂直切模块，子层按需：接口/实现/UI/Model
3. **服务层**：全局通用服务（网络、存储、认证、推送），对上暴露接口
4. **基础层**：通用组件、三方库封装、跨平台共享代码

### 架构原则
1. 严格分层 + 依赖只能向下
2. 高度模块化，独立可测
3. 视图与业务逻辑解耦
4. 三端共享规范，平台实现分离
5. 单向数据流
6. 网络不可靠是设计前提

### 页面级模式
State + Action + Reducer + Effect（三端统一）

### AI 时代强化
- 模块自描述（接口 + 类型 + 文档 + 测试）
- 接口即规格书
- 模块粒度适配 context window
